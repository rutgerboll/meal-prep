# T0.2 — Close the two measured pipeline holes

**Status:** DONE · verdict **PASS**
**Scope covered:** `scripts/pre-commit` (8 cases), `app/deploy.sh` health check (4 server
states). **Not covered:** `deploy.sh`'s pull path — never executed, by design; the
dirty-checkout guard, which is T0.10's.
**Comparators:** hook verdict vs. probe commits (2 kinds: the hole, and the regressions) ·
health-check verdict vs. ground-truth `curl` codes vs. `lsof` LISTEN.
**Denominator:** state 2 (working tree). No claim about the phone; nothing was deployed.
**Prior findings read:** `findings/T0.1.md`, `knowledge/instruments.md`.

## Headline

Both guards now fail the cases they were letting through: `app/js/*.js` can no longer be
committed without a `CACHE` bump, and `deploy.sh` refuses a server that listens but does not
serve. **Deploy is still blocked** on T0.10 — a green T0.2 is not a working deploy.

## What changed

**`scripts/pre-commit`** — the guarded set is now a single `GUARDED` pattern covering
`app/index.html`, `app/js/*.js` and `app/styles/*.css` (the last for T0.7, which creates them),
rather than one hardcoded filename. The error message names the offending files. Reinstalled at
`.git/hooks/pre-commit`, verified byte-identical.

**`app/deploy.sh`** — three changes:

1. `lsof … LISTEN` replaced by two real requests. The two checks have deliberately different
   shapes: the app shell is polled (10×1s) to wait out startup; `/sync.json` gets **one**
   attempt with a 300s ceiling, because it re-runs `build_seed.py` per request.
2. The fallback now kills **by port** (`lsof -ti :$PORT`) instead of
   `pkill -f "python3 .*meal-server.py"`. That pattern matches every instance on the machine
   including a session's own test server — it is how T0.1 restarted production by accident, and
   leaving it would contradict CONTRACT §3, which now warns against it by name. Small fix in a
   file I was already editing; declaring it rather than burying it.
3. A distinct message when something holds the port but is not serving — the outage's exact
   shape, previously reported as `✓ Server is up`.

The last one matters and was not in the brief: removing a precached file also needs a bump,
since `ASSETS` must change with it.

**Comparator B — the health check, against four server states.** Functions lifted verbatim from
`deploy.sh` (lines 34–50) and sourced, so the code under test is the shipped code:

| port | what it was | `lsof` LISTEN | ground truth | `deploy.sh` verdict |
|---|---|---|---|---|
| 8766 | real `meal-server.py` | yes | 200 / 200 | **HEALTHY** |
| 8767 | `http.server` on an empty dir | yes | 404 / 404 | **UNHEALTHY** |
| 8768 | `http.server` on `app/` | yes | **200** / 404 | **UNHEALTHY** |
| 8799 | nothing | no | — | **UNHEALTHY** |

8767 is the outage shape: `lsof` says yes, the old check would have printed ✓. 8768 is the case
I added after the fact and the most instructive — the shell serves perfectly and only the data
path is broken, which a shell-only check would pass and the phone would still fail on.

## What could break this

- **The 300s ceiling on `/sync.json` is a judgement, not a measurement.** I set 45s first and it
  produced a **false negative**: a cold `.thumb-cache.json` in a fresh worktree pushed the
  rebuild past 45s (T0.1 measured 7.4s cold on a warm machine — under contention it is far
  worse). 300s is generous for the mini's warm cache; a fresh clone with 52 photos could still
  exceed it. If it ever fires spuriously, the answer is to warm the cache before deploying, not
  to raise the number again.
- **`GUARDED` and `sw.js`'s `ASSETS` are two hand-maintained lists** that must agree. This hook
  makes a *changed* precached file safe; a *new* file added to `app/js/` but never added to
  `ASSETS` is still invisible. T0.4's suite is where that assertion belongs, and its brief
  already names it.
- The hook only sees staged paths. `git commit --no-verify` still bypasses everything.
- Health is checked on `127.0.0.1`. It does not prove the Tailscale path works.

## Confidence

**High** on the hook (eight cases, real commits) and on the health check discriminating all
four states.

**Weakest link:** I never ran `deploy.sh` end to end — the brief forbids it because it pulls,
and the dirty-checkout guard blocks it anyway until T0.10. So the functions are proven and
their *integration* is not: I have not observed `deploy.sh` complete a real deploy. That is the
honest gap, and T0.10 is where it closes.

## What a full pass needs

1. **T0.10**, then one real `deploy.sh` run, deliberately, from the main checkout.
2. T0.4's suite to assert `ASSETS` ≡ `app/js/*` ≡ script tags — the hole this hook cannot see.
3. A recurrence check that runs without a deploy. The outage lasted three days precisely
   because nothing asked the server anything.

## Reusable artifact

The health functions are self-contained and sourceable (`sed -n '34,50p' app/deploy.sh`), which
is how they were tested and how T0.4 can reuse them. Note the extraction must be a **line
range**: a `/^shell_code()/,/^}/p` pattern silently duplicates `wait_healthy() {` into a nested
definition that returns 0 for everything — my first run reported all three ports healthy,
including a dead one.

## Portability annotation

- **Generic:** "check health with a request, not a port" and "kill by port, not by process
  name" carry anywhere.
- **This-app-specific:** the `GUARDED` pattern, the two-shaped health check, the 300s ceiling.
- **Library-schema-specific:** nothing.

A **fresh clone** still needs `cp scripts/pre-commit .git/hooks/pre-commit && chmod +x` — the
hook cannot install itself, and this task did not change that.
