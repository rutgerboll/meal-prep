# T0.9 — One design-system doc

**Status:** DONE · verdict **PASS**
**Scope covered:** both design documents read in full; archive move; inbound-reference sweep.
**Comparators:** the two documents against each other · both against the code
(`app/styles/*.css`, `grep` for `--space-*` and `prototype.html`).
**Denominator:** state 1 — committed repo. No app surface touched.
**Prior findings read:** `findings/T0.8.md`, `knowledge/structure-proposal.md`.

## Headline

`DESIGN-SYSTEM.md` is now the only document claiming design authority. The 383-line "Spiced
Linen" spec is archived with a header saying plainly that it is history — and the checks I ran
before moving it found that **its most tempting section was never implemented**, which is worth
more than the move itself.

## What changed

- `design/design-system.md` → `docs/archive/design-system-v1-spiced-linen.md` (`git mv`, so
  history follows). The `design/` directory is gone.
- The archived copy opens with an ⚠️ ARCHIVED block: what superseded it, when, that its colours
  and type are wrong for the current app, and **"Do not build from this document."**
- Its self-description as *"the source of truth for the engineer and the basis for the
  `prototype.html`"* is struck and replaced with a note that both claims are false — the
  sentence was the actual defect.
- `DESIGN-SYSTEM.md` gained a paragraph stating it is the only authoritative document, pointing
  at the archive, and saying what the archive still holds.

**One stale line fixed while I was in there.** `DESIGN-SYSTEM.md` said the source of truth for
tokens was "`app/` `<style>` (the appended Sage block)". T0.7 and T0.8 made that false; it now
points at `app/styles/01-tokens.css`, where each token is declared exactly once. The design doc
had been describing the very structure this wave dismantled.

## Evidence

**Nothing referenced the stale path.** `grep -rn "design/design-system"` across the repo returns
only program artifacts *describing it as the problem* (T0.5, T0.6, T0.9 briefs,
`knowledge/structure-proposal.md`, LOG). No code, no `CLAUDE.md`, no `ROADMAP.md`, no spec. The
document had authority in its own text and nowhere else — which is exactly how it misleads a
reader who finds it by browsing.

**The carry-over question, answered by checking rather than assuming.** The brief warned not to
equate length with value. Reading both in full, three sections of the old doc are genuinely
absent from Sage: the 4px **spacing scale** (§4), **iconography** (§6), and **mobile interaction
patterns** (§7 — gestures, 44×44 hit areas, sticky CTAs, keyboard/`inputmode`). Tempting to
promote. But:

- `grep -c '\-\-space-' app/styles/*.css` → **0 in all four files.** The spacing scale was never
  implemented. Promoting it into the authoritative doc would have published a fiction as spec.
- `prototype.html`, which §5's component anatomy is written against, **does not exist** in this
  repo.
- Tap targets ≥44px — the one §7 rule that matters most — is *already* in `DESIGN-SYSTEM.md`.

So I carried across a **labelled pointer**, not the content: the current doc names those three
sections as "unverified proposals, not a record of the code", and says to check them against the
app before promoting anything. That keeps the material findable without minting a second source
of false authority, which is the failure this task exists to fix.

## What could break this

- **`docs/` now exists with one tenant.** If T0.11 declines the directory move, `docs/archive/`
  sits beside `spec/` and `logs/` as a third documentation location — marginally worse than
  before on tidiness, better on truth. T0.11 should fold `spec/` and `logs/` in, or decide not
  to and say so.
- The archive header asserts the supersession date as 2026-06-27, taken from
  `DESIGN-SYSTEM.md`'s git history rather than from a decision record. It is the best available
  date, not a certain one.
- `logs/` still holds five June documents (`test-report-*.md`, `planner-review.md`,
  `feedback-log.md`, `change-log.md`) with no header saying whether they are current. Same class
  of problem, smaller blast radius, out of scope here.

## Confidence

**High.** The move is mechanical, the reference sweep is exhaustive (`grep -ril` across every
`*.md`), and the two "is this still true?" checks are code greps rather than judgement.

**Weakest link:** whether the three carried-over sections *should* have been promoted rather
than pointed at is a judgement call, and I made it conservatively. If the spacing scale is
something the user wants the app to actually follow, my choice defers that work instead of
doing it — T0.5's audit is the right place for that to surface, and its brief already covers
spacing.

## What a full pass needs

1. T0.5 to decide whether the archived spacing scale and interaction patterns should be
   implemented, and if so promote them into `DESIGN-SYSTEM.md` at that point.
2. A `docs/README.md` index — the sprawl T0.6 flagged (15 documents, no map) is untouched.
3. `logs/`'s five June files need the same "is this current?" header treatment.

## Reusable artifact

The archive header pattern: **supersession date + what replaced it + which specific sections are
wrong + what is still worth reading + "do not build from this document."** A bare "ARCHIVED"
banner would not have stopped a reader mining §4 for a spacing scale the code never had.

## Portability annotation

- **Generic:** archive rather than delete; strike the authority claim *inside* the archived copy;
  verify "still true?" with a grep against the code, not by reading the prose.
- **This-app-specific:** the file paths, the Sage/Spiced Linen history, the `--space-*` finding.
- **Library-schema-specific:** nothing.
