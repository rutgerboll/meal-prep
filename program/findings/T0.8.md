## Headline

Every design token is now declared exactly once, and **`!important` is down from 20 to 4** —
the four `.hidden` display utilities, which are a legitimate pattern and were never the
problem. All 10 screen×theme computed-style hashes are unchanged.

## What changed

**1. The dead token layer is gone.** `01-tokens-legacy.css` deleted. Its two survivors, `--nh`
and `--font`, were carried into the Sage token block — which moved to the front as
`01-tokens.css`. Moving tokens earlier is safe *because* the competing set no longer exists;
custom properties only contend with other declarations of the same name.

**2. The overrides were collapsed, not just stripped.** This is the part the brief was right to
insist on. Sage's `!important` rules existed to neutralise glassmorphism still sitting in the
base layer. Deleting the `!important` alone would have brought the frosted-glass look *back*.
So for each of five rules I rewrote the base declaration to the value Sage was forcing and then
deleted Sage's override entirely:

| selector | base declared | now declares | Sage override |
|---|---|---|---|
| `#nav` | `var(--navglass)` + `backdrop-filter:blur(24px) saturate(180%)` | `var(--bg-card)` | deleted |
| `.card` | `var(--glass)` + blur + `box-shadow:0 4px 20px …` | `var(--bg-card)`, `border:1px solid var(--bdr)`, `box-shadow:none` | deleted |
| `.sticky` | `var(--navglass)` + blur | `var(--bg-card)` | deleted |
| `.sheet` | `var(--glass-strong)` + blur | `var(--bg-card)` | deleted |
| `.fld input/select/textarea` | `var(--glass)` + blur | `var(--bg-alt)` | deleted |

`html,body{background:var(--bg-app)!important}` was deleted outright — it forced the value the
base layer already set. A pure no-op that had been carrying an `!important` for nothing.

**3. The patch layer folded in.** `#nav`'s safe-area height and `.ssec`'s typography were
overriding base rules with `!important`; both are now declared once in `02-base.css`.
`04-patches.css` keeps its three genuinely-additive rules and carries no `!important`.

**4. The obsolete install comment is gone** — 14 lines telling a reader how to install a system
that is installed, including the paste-it-after-and-let-`!important`-win shortcut that caused
all of this.

## What I did not do, and why

The brief's final step was renaming to `tokens.css` / `base.css` / `components.css` /
`screens.css`. **I stopped at `01-tokens.css` + `02-base.css` + `03-sage.css` +
`04-patches.css`.**

That rename is not a rename: sorting rules into "components" and "screens" means interleaving
`02-base.css` and `03-sage.css` by category, which reorders rules across the boundary where
same-specificity conflicts are currently resolved by source order. The empty-diff test would
probably catch a mistake — but "probably" is doing real work in that sentence, and the payoff is
naming. The current four files are ordered, prefixed, and each has a one-line header saying what
it holds. **Filed as a follow-up rather than done badly**, and T0.11 may make it moot anyway.

**The instrument, finally working.** T0.7 failed to run this because the hidden browser pane

in the same call works, and the whole 10-combination battery now runs in **2 ms**. That is the
reusable artifact.

**Live CSSOM census after the change:** `01-tokens.css` 2 rules, `02-base.css` 139,

## What could break this

- **The service worker fought me the entire task, and it will fight the next person.** Its
  fetch handler is cache-first, so edited CSS keeps being served stale from cache; a `CACHE`
  bump alone was not enough within a session. I twice measured what I thought was new CSS and
  was actually reading the old files — caught both times only because a rule count did not match
  the disk. **Verify you are measuring what you think you are** (compare a sheet's `cssRules.length`
  against the file) before trusting any result. Unregistering the SW and clearing caches is what
  finally worked.
- `--nh` and `--font` are the one-line difference between this task and a broken app. They
  resolve correctly (`64px`, `system-ui,…`) in both themes.
- The `.glass` / `.glass-strong` **classes** are unused (0 occurrences); the `--glass*`
  **tokens** are still live. Do not "clean up" the tokens on the strength of the class names.
- `03-sage.css` is now a component-styling file with a design-system name. If T0.9 lands and the
  docs settle on one system, the file name will read as the odd one out.
- CACHE went v27 → v31 across T0.7/T0.8 because I bumped it per verification round. Harmless,
  but it means the version number no longer counts releases.

## Confidence

**High.** Ten independent screen×theme hashes, unchanged across three separate edit stages, plus
a rule census that matches the files on disk, plus a matching screenshot.

**Weakest link:** the sampler takes **one element per distinct `tag.className` signature** — 39
on the plan screen, not all 462 elements. A change affecting only the *second* `.card` on a
screen and not the first would slip through. Given every edit here was to a rule, not a
selector, that is a narrow gap, but it is real. Also: the light theme was measured by setting
`data-theme` directly rather than through whatever UI toggles it, so a bug in the toggle itself
is out of scope by construction.

## Reusable artifact

The zero-timer measurement pattern — the thing that made this task possible:

```js
const run = (theme, route) => {           // no await, no sleep: the app renders synchronously
  document.documentElement.dataset.theme = theme;
  navigate('#/more');                     // fixed predecessor — the plan screen's DOM
  navigate(route);                        // depends on where you came from
  return measure();
};
```

10 combinations in 2 ms. With `await sleep()` between navigations it times out at 30 s, because a
hidden browser pane throttles timers, not style reads. `knowledge/instruments.md` carries it.
