## Why this task exists

There is **no test suite in this repo at all** — `logs/test-report-*.md` are prose reports from
June, not executable. Every verification so far has been a session driving a browser by hand.
That is why the board cannot take orchestrated workers: the spawn gate needs one command it can
run on the base branch and see go green.

The secondary payoff is larger than the orchestration one. T0.1 measured three failures that a
five-minute smoke test would have caught immediately: a server serving 404 behind a live port
for three days, a bootstrap 20 plan entries out of date, and a hook that lets `app/js/*.js`
through. None of those needed a clever test.

## Objective

A suite that runs in seconds with **no new dependencies** (no npm, no pip installs — the
keyless/no-build-step constraint is a settled decision, `program/README.md` §Anti-patterns),
plus `tm orch config --suite-cmd` pointing at it.

## Suggested first tests — smoke level is explicitly enough

Prefer things that would have caught a real past failure over things that are easy to assert.

1. **Seed builds and validates.** Run `build_seed.py` into a temp dir; assert it exits 0, that
   `meta.schemaVersion == 3`, that recipe/plan/entry counts are non-zero, and that
   `aisle:pantry remaining` is 0. Baseline numbers are in `knowledge/instruments.md`.
2. **Bootstrap matches the seed.** Parse the inline `const SEED` out of `index.html` and diff
   its plan entries against a fresh `seed.json`. This is exactly the T0.3 drift, and it is the
   single highest-value assertion in the list.
3. **Asset lists agree.** The `app/js/*.js` on disk, the `<script src>` tags in `index.html`,
   and `sw.js`'s `ASSETS` array must be the same set (16/16/16 today). A file missing from
   `ASSETS` is invisible until an installed phone goes offline.
4. **The server answers.** Start `meal-server.py` on a spare `MEAL_PORT`, assert 200 on
   `/index.html` and `/sync.json`, stop it **by PID**. See the trap below.
5. **The hook holds.** Once T0.2 lands, assert a staged `app/js/*.js` change without a `CACHE`
   bump is rejected.

## Out of scope

- Testing app behaviour in a browser. Headless browser automation is a bigger commitment than
  this task; if you think it is warranted, file it rather than starting it.
- Fixing anything the suite finds red. Write the test, let it fail honestly, file the fix.
  A suite the gate needs green is a real tension here — say plainly which tests are red on
  arrival rather than weakening them to pass.

## Known traps

- **Never `pkill -f meal-server.py`.** It matches the launchd server the phone depends on;
  T0.1 restarted production that way. Stop test servers by PID:
  `kill $(lsof -ti :8766 -sTCP:LISTEN)`.
- **Never let a test run `build_seed.py` into `app/`.** That is the file the live server owns
  (GOTCHAS 2026-08-04). Build into a temp dir, or accept that the suite mutates production
  data — and it must not.
- Set `MP_BASE_DIR` explicitly. A worktree run without it dies on `../../recipes`, which will
  read as a broken test rather than a missing env var.
- The suite must be **runnable from a worktree**, since that is where orchestrated workers
  live.
- Timing: a cold `build_seed.py` is 7.4 s (52 thumbnails through `sips`), warm is 0.10 s. A
  fresh worktree always pays cold. Do not write a timeout that assumes warm.

## Done when

One command runs green from both the main checkout and a worktree, `tm orch config --suite-cmd`
is set to it, `findings/T0.4.md` per CONTRACT §6 lists what each test would have caught, and
anything red on arrival is filed rather than silently weakened.
