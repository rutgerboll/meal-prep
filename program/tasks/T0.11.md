## Why this task exists

`app/` currently holds four unrelated kinds of thing in one flat directory: a browser client, a
build tool, a web server, a deploy script, and ~2 MB of generated data. The proposed division
is by role, so that where a file goes stops being a question about history:

```
client/     what the phone runs — index.html, styles/, js/, assets/, sw.js
pipeline/   markdown → seed — build_seed.py, embed_seed.py
server/     what runs on the mini — meal-server.py, apply-feedback.py, deploy.sh, the plist
dist/       generated, gitignored (T0.10 may already have created this)
docs/       spec/, the one design-system doc, archive/ for the superseded five
```

The rule that carries most of the value: **`client/` contains only what the phone runs.** Today
`deploy.sh` and `build_seed.py` sit beside `sw.js`, which is why nobody can tell at a glance
what ships.

## Every path that breaks — verified list, extend it if you find more

- `app/sw.js` — `ASSETS` are relative and survive, but **`const CACHE` must be bumped**, and
  the service worker's *scope* changes if `index.html` moves. Read that carefully: a scope
  change can orphan an installed phone's registration.
- `app/meal-server.py` — `SCRIPT_DIR` (serves static files from it) **and**
  `SCRIPT_DIR/"../.."` for the feedback inbox path, which assumes the current depth.
- `app/build_seed.py` — `BASE_DIR` default `../..`, `THUMB_CACHE_PATH`, and the `seed.json`
  output path.
- `app/embed_seed.py` — `SEED_PATH` and `HTML_PATH`.
- `app/deploy.sh` — `SCRIPT_DIR/..` for the repo root.
- **`~/Library/LaunchAgents/com.mealplanner.server.plist`** — an absolute path to
  `meal-server.py`, outside the repo. Editing it needs a `launchctl bootout`/`bootstrap` cycle,
  and getting it wrong takes the phone's server down.
- `scripts/pre-commit` — two `^app/` patterns (more after T0.2 and T0.7).
- `CLAUDE.md`, `program/CONTRACT.md` §2/§3/§8, `knowledge/instruments.md`, and every brief in
  `program/tasks/` that names a path.
- The docs mirror publishes files that program documents cite **by path** — moving a cited file
  changes what the phone can read.

## Known traps

- **`deploy.sh` must be working before you start.** T0.10 restores it; it is the rollback path.
  If it is still broken, stop — that ordering is the whole reason this task is gated.
- **The mini is this machine.** There is no second host to break separately, and the server is
  live while you work. A move that breaks static serving breaks the phone immediately, not at
  the next deploy.
- **`tailscale serve` proxies to port 8765**, not to a path — it survives the move. Confirm
  rather than assume.
- Use `git mv` so history follows. A delete-plus-add loses the blame trail on the file that
  most needs it.
- Do this in a worktree, and verify the *whole* chain there before it reaches main:
  `build_seed.py` → `embed_seed.py` → serve → load → sync → feedback POST.

## How to prove it

Two comparators, both end-to-end:

1. **The full pipeline from a clean worktree**: build the seed (expect the known-clean baseline
   in `knowledge/instruments.md` — 35/304/5/98/71/20/52 and four expected WARNINGs), embed,
   serve on a spare `MEAL_PORT`, load the app, sync, POST feedback and confirm it lands in
   `feedback-inbox-test.jsonl`.
2. **The launchd server on 8765 after the move**, `curl`ed on a real path — plus the Tailscale
   URL the phone uses. A 404 here is the phone down.
