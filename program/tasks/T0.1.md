## Why this task exists

`program/CONTRACT.md` was drafted during onboarding by adapting the kit's *analysis*-shaped
template to a *build* program. It was written from `ROADMAP.md`, `CLAUDE.md`, and a skim of
`app/` — it has never been checked against a running app or a real seed build. Every claim
in it is plausible and unverified, which is exactly the state that makes a contract
dangerous: later tasks will treat it as binding.

## Objective

Establish, by exercising the real system, whether each of CONTRACT §1–§10 is true as
written; correct what isn't; then freeze it at v1.0. Specifically settle: does the
repo-state / installed-state split in §1 describe what actually happens on a phone; are the
§3 instruments real and reachable from a session; and are the §8 hygiene incantations
literally correct (copy-pasteable, not approximately right).

## In scope

- Run `build_seed.py` from **both** the main checkout and a worktree; confirm the
  `MP_BASE_DIR` trap in §8 and record the exact working incantation.
- Run `embed_seed.py`; confirm what it does and does not carry (thumbnails stripped?).
- Serve the app (`meal-server.py` or the browser pane) and confirm §3's "running app" is a
  usable instrument from inside a session, including a clean console check.
- Trace the service-worker update path: change a file under `app/js/`, confirm whether
  `scripts/pre-commit` catches it (GOTCHAS says it does not — verify, don't assume) and
  what an installed phone actually sees.
- Confirm §2's boundary: where the Claude-side skills physically live, and whether a
  session can even read them. **If they are not on this filesystem, say so plainly** — it
  changes what Wave 1 can be.
- Fix CONTRACT.md, bump to v1.0, add the freeze line and a changelog entry.

## Out of scope

- **Do not build any roadmap feature.** No Wave 1/2/3 work, however tempting.
- Do not change `app/` behavior. You may make a throwaway edit to test the sw path — revert it.
- Do not deploy to the Mac mini unless verifying the installed-state denominator requires
  it, and if you do, say so and leave the mini on a clean checkout.

## Known traps for THIS task

- The markdown library lives **outside the repo** in the parent `Meal planning/` directory
  and is shared with the Claude skills. Rebuilding the seed touches shared state — you are
  the only session running, keep it that way (README §Execution model).
- `app/seed.json` is already dirty in the main checkout (`git status`). Understand why
  before you overwrite it.
- A fresh IndexedDB is not evidence about migrations. If you test the installed-state
  claim, test against a browser profile that already has the app.
- `deploy.sh` refuses on a dirty checkout **by design**. That's the contract working, not a bug.
