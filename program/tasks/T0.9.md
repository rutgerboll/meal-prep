## Why this task exists

Two documents describe this app's visual language and both claim authority:

- **`DESIGN-SYSTEM.md`** (root, 66 lines) — *"v3: Sage … Supersedes the earlier 'Spiced Linen'
  (terracotta) system. Build all new screens from these tokens."* **Current.**
- **`design/design-system.md`** (383 lines, dated 2026-06-21) — *"**This document is the source
  of truth for the engineer** and the basis for the `prototype.html`."* **Stale**: it is the
  superseded terracotta system, six times longer, and it is the one that says it is
  authoritative.

This is the same abandoned migration as T0.8, recorded in prose instead of CSS. A reader who
finds the long one first gets a confident, wrong answer — and CONTRACT §9 makes the design
system the benchmark for anything visual, so this misdirection has teeth.

The smallest task on the board and one of the more valuable. It is deliberately not bundled
into T0.8: that one is a code change with a visual proof obligation, this one is a `git mv`.

## In scope

- Establish `DESIGN-SYSTEM.md` (Sage) as the single source of truth. If anything in the 383-line
  document is still true and not carried over — device metrics, spacing scale, component
  anatomy, rationale worth keeping — **move it across before archiving.** Read both fully;
  do not assume length means value, or that the short one is complete.
- Archive the old one rather than deleting it: `docs/archive/design-system-v1-spiced-linen.md`,
  with a header line saying what superseded it, when, and why it is kept. It is the record of a
  real design decision.
- Strike the "source of truth for the engineer" claim from the archived copy. That sentence is
  the actual defect.
- Fix every inbound reference. Check at minimum `CLAUDE.md`, `program/README.md`,
  `program/CONTRACT.md` §9, `ROADMAP.md`, `COOK-UX-BRIEF.md`, and the `program/tasks/` briefs.
  `grep -ril "design-system" .` is the honest sweep.

## Out of scope

- Any change to CSS or to the app. Documents only.
- The wider docs reorganisation into `docs/` (T0.11). Creating `docs/archive/` here is fine and
  is the first tenant; do not move the other twelve documents.
- Judging whether the app *conforms* to Sage — that is T0.5.

## Known traps

- **`prototype.html` does not exist** in this repo; the old doc references it. Note it in the
  archive header rather than chasing it.
- The docs mirror publishes what program documents *cite by path*. Moving a cited file changes
  what the phone can read — re-render (`tm render`) and confirm the board still serves what it
  should.
- The archived file must stay readable. Do not `.gitignore` it.

## Done when

Exactly one document claims to be the design system, the archived copy says plainly that it is
history, every inbound reference resolves, and `findings/T0.9.md` lists what was carried across
before archiving.
