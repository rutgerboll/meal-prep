## Why this task exists

`app/seed.json` is tracked by git **and** rewritten by `meal-server.py` on every `/sync.json`
request. So the main checkout is dirty permanently, and `deploy.sh` — which refuses on a dirty
checkout, correctly — **can never run.** The documented deploy path is dead by construction,
which also means there is no rehearsed rollback when anything else goes wrong on the mini.

That is the real cost. The tidiness argument (generated artifacts do not belong in source
control) is secondary to the fact that the one recovery mechanism is disabled.

Verified by T0.1: a fresh `build_seed.py` reproduces the uncommitted `seed.json`
byte-for-byte, and `HEAD`'s copy is the stale one — so the dirty file is the *correct* one and
the committed one is the artefact of a past accident.

## The decision this task owns

T0.2 makes `deploy.sh`'s health check honest; **this task owns the dirty-checkout half.** Two
options — pick one, implement it, and justify it in the finding:

- **(a) Untrack and ignore.** `git rm --cached app/seed.json`, add it and `.thumb-cache.json`
  to `.gitignore`. Clean, and it is what the file already is. Cost: a fresh clone has no seed
  until it builds one, and a build needs `MP_BASE_DIR` and the parent library — so a clone
  without the library cannot produce a working app at all. Say whether that matters.
- **(b) Keep tracking, exempt it from the guard.** Narrow the `git status --porcelain` check to
  ignore that one path. Lower blast radius, but leaves a tracked file that mutates under you
  and keeps every `git add -A` dangerous (`knowledge/prioritization.md` G5).

The proposal in `knowledge/structure-proposal.md` leans (a) with a `dist/` directory. **Moving
the file is optional and separable from untracking it** — the location change costs path edits
in four scripts (`build_seed.py`'s output path and `THUMB_CACHE_PATH`, `embed_seed.py`'s
`SEED_PATH`, `meal-server.py`'s read, plus `deploy.sh`), and the app fetches nothing from
`seed.json` at runtime (it boots from the inline `SEED` and syncs from `/sync.json`), so the
move is cheaper than it looks. Decide; do not assume.

## Known traps

- **The server is live and rewrites this file while you work.** Expect the tree to go dirty
  under you mid-task; that is the bug, not your mistake.
- **`git rm --cached` on a file the running server holds open is fine, but do not `git rm` it.**
  Deleting `app/seed.json` from disk breaks the next sync until a rebuild — and the phone is the
  thing that notices.
- **Do not run `deploy.sh` to test it.** It does `git pull --ff-only origin main` against
  GitHub. Exercise its guards in isolation, then run it once, deliberately, when you believe it
  is right — and only from the main checkout, which is on the mini (this machine).
- After any change, prove a sync still works: `curl` `/sync.json` and check the byte count
  (~1,087,727 today) and that `meta.schemaVersion` is 3.
- `.thumb-cache.json` is already `.gitignore`d — check before "fixing" it.
