## Why this task exists

`build_seed.py` does not refresh the inline `const SEED` in `index.html`; `embed_seed.py` is a
separate step, and it was skipped. T0.1 measured the drift: the committed bootstrap disagrees
with the markdown library on **20 plan entries** (batch `8 → 4`, lunch `2 → 1` on the
2026-07-26 plan). All other keys are equal.

This is invisible while the Mac mini is reachable — the app auto-syncs on load and IndexedDB
is corrected within about a second. It is *not* invisible when the mini is down, which as of
2026-08-04 it is: a fresh install then shows wrong servings with nothing to indicate it.

Small task, but do not batch it into an unrelated commit — this touches the user's real plan
data (`knowledge/prioritization.md` G5).

## In scope

Run the §8 chain from the main checkout, verify, commit `app/index.html` **and**
`app/seed.json` together with a message that says regenerating them *is* the change:

```
cd app && MP_BASE_DIR="/Users/rutgerboll/Documents/Claude/Projects/Meal planning" python3 build_seed.py && python3 embed_seed.py
```

`build_seed.py` must be re-run first — CONTRACT §2 forbids trusting an earlier session's
`seed.json`, and the library may have moved again since 2026-08-04.

## Out of scope

Everything else in `app/`. If the re-embed produces a diff you did not expect (anything beyond
plan-entry values and thumbnails), stop and log it rather than committing.

## Known traps

- **Does `index.html` changing require a `const CACHE` bump?** `scripts/pre-commit` will
  demand one and it is right to: the shell is precached, and installed phones will not pick up
  a new bootstrap without it. Bump it — but note the bootstrap only matters pre-first-sync, so
  say in the finding what the bump actually buys.
- Verify against the library, not against the previous `seed.json`: `grep servings`
  `meal-plans/2026-07-26-two-weeks.md` and check the number you shipped matches.
- Confirm the strip still happens — `embed_seed.py` should report 52 thumbnails stripped. A
  bootstrap that suddenly gained ~1 MB means the strip broke.
