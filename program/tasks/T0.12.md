## Why this task exists

`app/index.html:14` loads the heading font from Google:

```
<link href="https://fonts.googleapis.com/css2?family=Schibsted+Grotesk:wght@400;500;600;700&display=swap" rel="stylesheet">
```

**`app/sw.js` precaches nothing from that origin** (`grep -c fonts app/sw.js` → 0). So
`--font-head: 'Schibsted Grotesk'` — which styles every screen heading, the Cook screen title,
section headers, recipe titles — silently falls back to `system-ui` whenever the phone is
offline or the tailnet is down.

Two reasons that matters more than it looks:

1. **The app's whole premise is offline-first in a kitchen.** The one place the typography is
   guaranteed to degrade is the place the app is meant to work.
2. **This app is deliberately keyless and private** (`program/README.md` §Anti-patterns; an
   in-app API key was built and then removed for exactly this reason). A third-party request on
   every load, carrying the phone's IP and user agent to Google, is at odds with that — and
   nobody chose it; it arrived as line 3 of the Sage design system's install instructions.

Found by T0.1 while measuring the CSS, not by a font complaint. Nobody has reported it, which
is consistent with the failure being invisible: a fallback font looks like a design choice.

## In scope

- Download the four weights actually used (400/500/600/700), `woff2` only.
- Put them in `app/assets/fonts/` (or `client/assets/fonts/` if T0.11 has landed — check, do
  not assume) and check them into the repo. They are small and this app has no build step.
- Replace the `<link>` with `@font-face` rules in `app/styles/tokens.css`, keeping
  `font-display: swap`.
- Add every font file to `sw.js`'s `ASSETS` and **bump `const CACHE`**.
- Confirm the licence permits self-hosting and record it. Schibsted Grotesk is SIL OFL, which
  does — verify rather than take this brief's word, and keep the licence file alongside the
  fonts.

## Out of scope

- Changing the typeface, the weights used, or any type scale. If a weight turns out to be
  unused, note it in the finding; do not drop it as part of this task.
- The second, duplicate `<link>` inside the Sage block's install comment (line 168) — that is
  a comment, and it dies with T0.8.

## How to prove it

The offline case *is* the test, and it is the one nobody ran:

1. Load the app, let the service worker install, then go offline (DevTools offline, or stop the
   server) and reload. Read `document.fonts.check('600 30px "Schibsted Grotesk"')` — **`true`
   offline is the whole deliverable.** Confirm it is `false` today before you start, so you
   have a before as well as an after.
2. Second comparator: `read_network_requests` shows **no request to `fonts.googleapis.com` or
   `fonts.gstatic.com`** on a normal load, and a screenshot of a heading matches the pre-change
   one.

## Known traps

- **Two origins, not one.** `fonts.googleapis.com` serves the CSS; `fonts.gstatic.com` serves
  the font files. Removing only the `<link>` and leaving a `@font-face` that points at gstatic
  fixes nothing.
- **Bump `CACHE`** or installed phones never fetch the new assets — and this task is *only*
  about installed phones.
- The service worker's fetch handler is cache-first and precaches by exact URL. Font files must
  be in `ASSETS` with paths that match how the CSS requests them, or they are fetched from the
  network at runtime and you are back where you started.
- Certify the server before measuring (CONTRACT §3).

## Done when

No request leaves the machine on a normal load, `document.fonts.check(...)` is `true` while
offline, headings render identically online, `CACHE` is bumped, the licence sits with the
fonts, and `findings/T0.12.md` per CONTRACT §6 records the before/after of the offline check.
