## Why this task exists

The app ships **two complete, conflicting design-token sets**. The "Spiced Linen" terracotta
set is declared first and the "Sage" set is pasted after it, winning by cascade order and
`!important` — which is the shortcut Sage's own install comment offers verbatim: *"or just
paste this whole file into a `<style>` AFTER the existing one — the `!important` overrides will
win."* It was taken, and the migration was never finished.

The cost is not bytes. It is that `--pr` reads `#B05334` (terracotta) in the first place a
reader looks and `#4C7C5A` (green) in the place that actually wins, so nobody can answer what
this app's colours *are* — which is the question that started wave 0c.

## What is dead, precisely — measured, but verify before deleting

- Block 1's `:root` declares **31 tokens; 29 are overridden** by Sage. Only `--nh` and `--font`
  survive.
- Block 1's `html[data-theme="dark"]` declares **29 tokens; all 29 are dead.**
- **Block 1's 125 base selectors are LIVE.** Only the token layer is dead. Deleting the block
  wholesale breaks the app — this is the single most important sentence in this brief.

## The `!important` declarations split into two kinds

There are 20. They are not one problem:

**Keep (4) — a legitimate utility pattern**, nothing to do with the migration:
`.ov.hidden`, `.conf-ov.hidden`, `#loading.hidden`, `.hidden` — all `display:none!important`.

**Retire (≈15) — pure block-order compensation.** Sage's block neutralises the old
glassmorphism that is still sitting in block 1: `backdrop-filter:none !important`,
`-webkit-backdrop-filter:none !important`, `background:var(--bg-card) !important`,
`border:… !important`, `box-shadow:none !important`, plus `#nav,.sticky`, `.sheet`,
`.fld input,…`, `html,body`, and block 3's `#nav` / `.ssec` overrides.

**Every one of those exists only because the rule it fights is still in the file.** Delete the
superseded rule and the `!important` becomes unnecessary. That is the actual repair; removing
the tokens alone leaves the scaffolding standing.

Treat the counts above as T0.1's measurement, not as gospel — re-derive them against
`app/styles/tokens.css` as T0.7 left it, and say so if they moved.

## In scope

1. Delete block 1's dead `:root` and dark token declarations, keeping `--nh` and `--font`
   (move them into the Sage token block rather than orphaning them).
2. Delete the superseded glassmorphism and card/sheet/input rules that Sage overrides —
   the three known collision selectors are `.card`, `.sheet`,
   `.fld input,.fld select,.fld textarea`.
3. Drop each `!important` that was only compensating for order. **One at a time, re-measuring
   after each** — a batch delete gives you no way to tell which one mattered.
4. Fold block 3's patch layer into `screens.css` where it now belongs unaided.
5. Bump `const CACHE`.

## Out of scope

- Any new styling, token, or visual improvement. This is a subtraction task.
- Restyling to match `DESIGN-SYSTEM.md` more closely — that is T0.5's finding to make, not
  yours to act on. Use the doc only to confirm which set is meant to win.
- Self-hosting the font (T0.12) and the directory move (T0.11).

## How to prove it

Reuse T0.7's computed-style snapshot instrument — that is why T0.7 was told to save it.

- The correct diff here is **empty**, exactly as in T0.7. Deleting dead declarations is
  a no-op by definition; **any** non-empty diff means the declaration was not dead, so revert
  that specific deletion and record what it was actually doing.
- Second comparator: screenshots per screen in both themes, plus a clean console.
- Third, cheap and worth it: `grep -c '!important' app/styles/*.css` before and after, and the
  token count in `tokens.css`. State both numbers in the finding.

## Known traps

- **`--font` and `--nh` are load-bearing survivors.** Deleting them with their neighbours is
  the most likely way to break this task, and the breakage (fallback font, wrong nav height)
  is subtle enough to pass a glance.
- Light theme. The app boots dark; the light token path is where a wrong deletion hides.
- Bump `CACHE` — an installed phone that keeps the old CSS is stale permanently.
- Certify the server first (CONTRACT §3).

## Done when

`app/styles/tokens.css` declares each token exactly once, the surviving `!important` count is
the 4 `.hidden` utilities (or the finding explains each extra), the computed-style diff across
five screens × two themes is empty, and `findings/T0.8.md` per CONTRACT §6 records the
before/after counts.
